## Sam on HyperBEAM

### Quick read:
Today’s HyperBEAM work is about fewer silent failures for node operators.

The biggest fix is in paid request handling. PR #1071 fixes an edge case where a payment node sitting in front of a tunnel could drop the original hook request, causing the tunnel to miss its relay target. In plain terms: a broker could handle a public request locally instead of forwarding it, creating an outage with no clear error. The fix preserves the request and finds the right p4 payment handler when more than one request hook is present.

There were also two operator-quality fixes: Hyperbuddy metrics now return a parseable content type for Prometheus-style monitoring, and the file-backed store now has tighter path constraints. That fits the recent pattern: after cleaner contribution rules last week, today’s work moves back into making the node less fragile in the places real operators notice first.

### Why it matters:
- Better paid routing means service nodes can be easier to trust and debug when requests pass through payment and tunnel layers.
- Better metrics and safer file-store paths make nodes easier to run, monitor, and harden without asking operators to understand every internal edge case.

### What stands out:
Good progress on real-node reliability. The work is not flashy, but it targets concrete failure modes: requests going to the wrong place, metrics getting rejected, and storage paths needing tighter limits.
