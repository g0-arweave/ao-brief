## xylophonez public repos

Quick read:  
The main move today was a cleaner paid remote bundler profile in `xylophonez/lapee-bundler-profile-ng`. For builders and operators, the useful part is simple: there is now a config path where uploads require payment, free bytes are set to zero, and the recharge ledger is left out on purpose.

That matters for anyone testing paid upload flows. The PR notes say the profile keeps AO payment, dynamic byte pricing, `bundler-free-byte-limit: 0`, configurable `bundler-premium`, and no sponsored recharge allowance. It also includes a QEMU smoke test where an upload without auto-funding failed with HTTP 402, while an auto-funded upload succeeded locally and fetched back the same payload.

There was also follow-up hardening on the recharging profile: a grace fix for the 24-hour recharging cycle and updated `recharging-ledger@1.0` IDs. In the recent context, this continues the same line of work: make bundler payment profiles less fragile, easier to share, and easier to verify with small JSON profiles instead of one-off local setup.

Why it matters:  
- Easier setup: operators get clearer profiles for paid-only bundling versus recharge-backed bundling.  
- Fewer payment edge cases: explicit 402 behavior and successful funded upload tests make the expected path easier to trust.  
- Better sharing: pinned profile JSON files give other builders a cleaner starting point for running the same flow.

What stands out:  
Good progress on separating two real operating modes: paid remote bundling and recharging-based bundling. The work is small in code size, but practical because it turns payment behavior into something a builder can inspect, test, and reuse.
