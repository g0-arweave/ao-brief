# AO Weekly Synthesis - 2026-05-29

AO Weekly Synthesis  
Week ending: 2026-05-29

Short version:  
AO work got easier to debug, safer to run, and clearer to split between HyperBEAM core software and the new PermawebOS layer.

Why it matters:

HyperBEAM gained a better way to understand failed local test runs. The new flight recorder can turn test events into a static browser page, with filtering, stack traces, and timings, instead of forcing builders to rerun tests with different log flags.

The base HyperBEAM repo also got leaner. SNP and Green Zone support were removed from the base distribution and moved toward `permaweb/os`, which makes the core node software simpler while keeping more specialized secure-compute work in a separate place.

The new `permaweb/os` repo saw heavy work on AndEE, zone checks, payment accounting, build pinning, and operator config validation. In plain terms: more checks around what software is running, who can join, what gets paid, and what build inputs are trusted.

Main themes:

- Debugging got faster: HyperBEAM merged flight recorders for Forge tests, so failed runs can be inspected in a browser instead of dug out of noisy terminal logs.
- Private data got more care: multiple recorder and event changes redacted private fields before debug output is shared.
- HyperBEAM got smaller and clearer: SNP and Green Zone code left the base distribution and moved to the OS repo path.
- Sharing node features got sturdier: Forge publish, release packaging, architecture metadata, and missing-feature checks all saw fixes.
- PermawebOS hardened launch paths: AndEE, zone admission, operator config, payment accounting, TPM checks, and pinned builds all moved forward.

Who moved it forward:

- Sam pushed the main HyperBEAM work: flight recorder, Forge fixes, release-line cleanup, base distribution pruning, message matching, and test fixes.
- Sam also drove most of `permaweb/os`, especially AndEE packaging, zone rules, secure hardware proof checks, and launch-path hardening.
- charmful0x added the README alpha notice in `permaweb/os`, merged as PR #1, which helps set clearer expectations for early users.
