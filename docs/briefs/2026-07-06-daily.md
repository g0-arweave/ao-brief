## Sam on HyperBEAM

Quick read:  
HyperBEAM operators can now set a default minimum Lua sandbox through node options. In plain terms: a node can define the basic Lua capabilities it is willing to allow, and each message can still add its own more specific sandbox on top.

That is useful for anyone running AO infrastructure because it moves a safety baseline into node config, instead of making every app or message repeat it. It also gives operators clearer control over how Lua code runs on their node.

This follows the recent HyperBEAM pattern of tightening low-level paths: dependency upkeep, encoding path maintenance, and now safer Lua defaults. The common thread is making the node easier to run with fewer fragile assumptions.

Why it matters:  
AO apps need flexible execution, but node operators also need clear control over what they trust. This change helps both sides: builders can still define message-specific Lua behavior, while operators can set a sane minimum rule set for their own node.

What stands out:  
Good progress on making AO node operation less fragile. The work is small in commit count, but it touches a practical trust point: what Lua code is allowed to do by default.
