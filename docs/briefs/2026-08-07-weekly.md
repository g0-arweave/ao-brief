# AO Weekly Synthesis - 2026-08-07

AO Weekly Synthesis  
Week ending: 2026-08-07

Short version:  
HyperBEAM HTTPS access got a practical reliability pass: browser-routed tunnel traffic and slow responses should fail less often.

Why it matters:  
This week was small in commit count, but useful in effect. The fixes target the part users actually feel: opening a service through HTTPS and having the request reach the right place without timing out.

The first fix helps browser traffic route correctly through the TLS proxy. HTTP/2 does not send the normal `host` header, so the proxy now preserves the request authority explicitly instead of letting upstream routing break.

The second fix keeps slow tunneled responses from being cut off by default idle timeouts. That means fewer confusing `SSL eof` failures when a request is still working but has not sent data back yet.

Main themes:
- Browser access got safer because HTTP/2 requests now keep the right host information when proxied.
- Slow tunneled requests got more reliable because the TLS listener now waits longer before closing the connection.
- HyperBEAM add-ons for HTTPS and tunnels continue to move from “it works in a demo” toward easier operation under real web traffic.
- The work stayed focused: two small code changes, both aimed at user-visible failure cases.

Who moved it forward:
