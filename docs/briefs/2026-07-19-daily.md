## Sam on HyperBEAM

Quick read:  
Today’s HyperBEAM change fixes a practical reliability issue: when a message is signed on behalf of a user through `~auth-hook@1.0`, the node now honors the `store-all-signed` setting and commits that message to disk.

That is useful for app builders and operators because a message should not vanish from the local read path just because it came through a hosted-wallet style flow. The PR description is clear: it “ensures that messages signed on behalf of users,” protected by `~secret@1.0`, “are committed to disk and available to read back later.”

This follows the recent pattern in Sam’s HyperBEAM work: fewer edge-case failures around Arweave-linked storage, clearer operator controls, and more tests around paths that can affect real app behavior.

Why it matters:  
- Better app reliability: signed messages that a node accepts can be saved and fetched later under the expected config.  
- Clearer operator behavior: `store-all-signed` now applies in this auth-hook path too, which reduces surprise when running nodes.

What stands out:  
Good progress on making signed-message handling less fragile. The change is small, but it closes a real gap between operator config and what actually happens when messages enter through an auth hook.
