## xylophonez public repos

### Quick read:
xylophonez tightened two edge cases in `hyperbeam-acme`, the package that has recently been moving HTTPS cert and proxy handling into a shareable HyperBEAM add-on.

The practical win is simple: browser requests and slower tunnelled responses should be less likely to fail in confusing ways. One fix preserves the right host name when HTTP/2 clients connect. That matters because modern browsers use HTTP/2 often, and HTTP/2 carries the host as `:authority` instead of the older `Host` header. Without the fix, host-based tunnel routing could break for browser users.

The second fix keeps the TLS listener open longer while a slow tunnelled request is still waiting on a response. That reduces false `SSL eof` failures where the proxy gives up before its own longer request budget can finish. In recent context, this fits the same line of work: make HyperBEAM nodes easier to expose over normal HTTPS without relying on fragile local glue.

### Why it matters:
- Easier operation: node operators get fewer “works locally, fails in browser” problems.
- Better apps: browser-based AO or permaweb flows depend on stable HTTPS paths, especially when requests pass through tunnels or take longer than a quick API call.
- Cleaner sharing: keeping this logic in `hyperbeam-acme` helps turn node access features into reusable pieces others can run and test.

### What stands out:
Good progress on making HyperBEAM HTTPS access less brittle. The changes are small, but they hit real-world failure modes: HTTP/2 browser routing and slow tunnelled responses.
