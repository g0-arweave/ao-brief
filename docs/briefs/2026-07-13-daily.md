## xylophonez public repos

### Quick read:

The useful change: a HyperBEAM node can now be reached through a normal public domain without needing the node itself to accept inbound traffic. The new tunnel broker routes traffic like `<node-address-base32>.<your-domain>` to a node that keeps an outbound connection open, then relays the full HTTP response back.

That is practical for people running nodes behind home networks, phones, VPS firewalls, or other setups where inbound access is painful. The repo also added a real Namecheap + VPS deploy guide, with the commit title saying it was “proven on tunnel.permaweb.space.”

The work then got tightened: the tunnel repo moved away from a standalone launcher and toward a device-first setup — in plain terms, a feature a node can add through config instead of a separate one-off service. That fits the recent xylophonez pattern: payment route hardening, AndEE config tooling, and now simpler ways to run useful node features with fewer custom pieces.

### Why it matters:

- Easier public access makes HyperBEAM nodes more useful for real apps and testing, especially from constrained networks.  
- Config-based node features are easier to share, install, and trust than local scripts that each operator has to keep alive.  
- The ACME cert work points at less manual HTTPS setup, which matters if these nodes are meant to serve real traffic.

### What stands out:

Good progress on reducing setup friction for node operators. The work is not just “add a tunnel”; it also adds deploy docs, config fragments, a pinned Arweave implementation ID, and wildcard cert issuance.
